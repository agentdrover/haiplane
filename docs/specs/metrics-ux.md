## 3. Иерархия страницы

Порядок: ответ, затем тренд, затем разбивки, затем строки.

```
/metrics
├─ Шапка: заголовок, ссылка на Agent API usage
├─ Панель фильтров (sticky на десктопе): проект · период · модель · «сравнить»
│    + чипы активных фильтров
├─ 1. Общая картина          (6 карточек показателя)            → Q2, Q3, Q10
├─ 2. Проблемные места       (ранжированный список, 3–7 строк)  → Q1, Q4
├─ 3. Тренд                  (линия + накопленные исходы)        → Q5
├─ 4. Разбивки               (профиль, модель, харнесс, категория) → Q6
├─ 5. Распределения и утечки (cycle time, shift-left, прод-часы, экономика прогонов) → Q7, Q8, Q10
└─ 6. Строки                 (прежние таблицы + «как считается»)   → Q4, Q9
```

Правила:
- Первый экран без прокрутки на 1280×800 содержит фильтры, «Общую картину» и заголовок «Проблемных мест».
- Порядок §1–§2 (ответ) фиксирован и не зависит от данных.
- Все методологические абзацы уходят в §6 к своей таблице, в блок «как считается». Текст переносится дословно (тест #1487 AC-3).
- Раздел «Долг: категории без проверки» с §6 поднимается в «Проблемные места» (#956 AC-8). В §6 остаётся полная таблица.

Оси показателей остаются как в `practice_metrics`. Новых метрик и формул нет.

## 5. Компоненты

Компоненты — partials Jinja + CSS в `style.css`, без JS-фреймворка. Первые три делает #1487, графики — #1488.

### 5.1 Карточка показателя (`metric_card`)

```
┌ левая полоса статуса ─────────────────────────────┐
│ Название (text-secondary, 13px)                    │
│ 61%  (28 из 46 задач)      ← значение 28px, n рядом │
│ ▼ хуже: было 74% (n=39), −13 п.п.   ← направление словом + знак │
│ [спарклайн, если есть ряд]                          │
│ [оговорка о неполных данных, если есть]             │
│ поле-источник (mono 12px)         N строк →        │
└────────────────────────────────────────────────────┘
```

Параметры: `label`, `value`, `unit`, `n`, `prev_value`, `prev_n`, `direction` (`better|worse|flat|none`), `good_when` (`higher|lower`), `caveat` (текст или none), `sparkline` (ряд или none), `source_field`, `drill_url`, `drill_count`.

Правила:
- Статус несут три признака сразу: цвет полосы, знак (`▲` `▼` `≈`), слово («лучше», «хуже», «без изменений»). Цвет один не работает (WCAG 1.4.1).
- `▲`/`▼` показывают направление величины. Слово «лучше»/«хуже» зависит от `good_when`. Например, у цены `▲ дороже` = хуже.
- Порог «без изменений»: `|Δ| < 5%` относительного изменения или меньше 2 наблюдений разницы.
- Направление рисуется только при `n ≥ MIN_COMPARE_N` в обоих окнах (предложение: 10, решение владельца, §14). Иначе `сравнить не с чем` (#956 AC-2). Стрелка от нуля наблюдений не выводится никогда.
- Число `drill_count` совпадает с числом строк в списке, куда ведёт ссылка (#1493 AC-4). Если фильтр для счётчика выразить нельзя, ссылки нет, есть поле-источник.

### 5.2 Пустое состояние (`empty_state`)

Рамка пунктиром, заголовок жирным и одна фраза причины. Тексты:

| Причина | Заголовок | Пояснение |
|---|---|---|
| нет наблюдений | Нет данных за окно | Считать не из чего; это не ноль |
| мало наблюдений | Мало данных | n=… ниже порога …; доля не показывается |
| нет предыдущего окна | Сравнить не с чем | В предыдущем окне … наблюдений, нужно не меньше … |
| один пункт ряда | График не строится | Одна точка; показано значение и таблица |
| фильтр обнулил выборку | Ничего не найдено | Проект/модель/период без прогонов; кнопка «Сбросить фильтры» |
| нечего ранжировать | Проблемных мест не найдено | При выборке n=…; это не значит, что их нет |

«Нет данных» никогда не рисуется нулём, тире или пустой осью. Ноль печатается нулём только когда его посчитали (#912).

### 5.3 Спарклайн и график

Серверный SVG, без JS и без библиотек.

Спарклайн: 120×28, одна линия, без осей, `role="img"` и `aria-label` вида «Тренд X: с A до B, {рост|падение}».
Полный график (тренд): 320×150 в `viewBox`, масштабируется по ширине контейнера.

Правила графика:
- Подпись оси Y и X, 3–4 засечки.
- Предыдущее окно рисуется штриховой линией серым, текущее сплошной. Предыдущее окно не рисуется, если в нём нет наблюдений.
- Линия несёт метку значения на последней точке.
- Под графиком: легенда (§5.5), `<p class="sr">` с текстовым описанием (для скринридера), краткая фраза «С A до B за N недель; предыдущее около C» (для зрячих), свёрнутая `<details>` «Таблица значений» с теми же числами.
- Ряд из одной точки и пустой ряд: вместо графика пустое состояние (#1488 AC-2).

Столбцы разбивок: CSS-бары (`<ul>` с полосой), не SVG. Полоса имеет подпись значения справа и n. Столбец выборки меньше порога штрихуется и получает слово «мало».

### 5.4 Оговорка о неполных данных (`caveat`)

- Рядом с числом, в карточке и в строке таблицы, на тёмно-жёлтом фоне с рамкой слева. Цвет не единственный признак: перед текстом стоит слово «Оговорка:».
- Текст называет что не покрыто и сколько: «размечено 24 из 61», «без счёта 9 из 71 прогона», «стадия не записана у 8 из 28 дефектов».
- Оговорка видна всегда, в том числе когда блок «как считается» свёрнут. Под кат уходит объяснение, а не факт неполноты (#956 AC-6, #1487 AC-4).
- Когда покрытие полное, оговорки нет: пустая оговорка не рисуется.
- Все оговорки текстом `--text` (14:1), не `--text-muted` (3,5:1).

### 5.5 Легенда

Список под графиком: образец линии/квадрат + подпись. Не только цвет: у линий отличается штрих (сплошная / штриховая), у заливок штриховка (`repeating-linear-gradient`) для «неизвестно», «не разобрано», «мало». Значения (n, %) стоят прямо в подписи легенды.

### 5.6 Свёрнутый блок «как считается» (`how_it_works`)

`<details class="how"><summary>Как считается</summary>…</details>` у строки, к которой абзац относится. Текст дословный. Ссылки на задачи (#NNN) сохраняются. По умолчанию свёрнут. Кнопка-раскрытие не менее 28 px по высоте, на мобильном 44 px.

### 5.7 Таблица-дубль

У каждой диаграммы свёрнутая «Таблица значений» с теми же числами (#1488 AC-3). Числа диаграммы и таблицы берутся из одного объекта в шаблоне.

## 7. Экран «Проблемные места»

Ответ на Q1. Ранжированный список из 3–7 строк. Строка: ранг, тип, заголовок с числом, причина одной фразой (с указанием поля-источника), ссылка на строки `N строк →`.

Порядок (решение владельца по порогам, §14):

1. **Долг без проверки** (`category_debt[]`, `covered=false`). Внутри: по числу задач, затем по находкам. Причина: платим за повторное открытие категории на каждой сдаче.
2. **Пробитые правила** (`rule_breaches.breached[]`). Внутри: по числу находок после заведения.
3. **Ухудшения против предыдущего окна** (по ключевым показателям §4). Порог: относительное ухудшение ≥ 10% и `n ≥ MIN_COMPARE_N` в обоих окнах. Внутри: по относительному ухудшению.
4. **Пробелы данных**: `reconciliation.gap > 0`, `machine_reviews.dispositions.confirmed_unjudged > 0`, `shift_left.unknown_share ≥ 0.25`, `review_economy.runs.unbilled > 0`. Внутри: по размеру пробела.

Правила:
- Улучшившиеся показатели в список не попадают.
- Ухудшение без достаточной выборки в список не попадает и не рисуется стрелкой; вместо него в «Общей картине» стоит «сравнить не с чем».
- Максимум 7 строк, остальное «ещё N →» с переходом в §6.
- Оттенок строки (красная / оранжевая / синяя полоса) дублируется словом-меткой типа («долг без проверки», «правило пробито», «ухудшилось», «пробел в данных»).
- Сортировка стабильна: одинаковые по значению строки идут по названию, чтобы порядок не прыгал между перезагрузками.
- Реализация: ранжирование считает сервис (#1490), шаблон ничего не сортирует (#1493).

Для `/metrics/agent-api`: потолок близко (`used_pct ≥ headroom_warn_pct`), инструменты с `error_rate` выше порога, неиспользуемые инструменты.

## 8. Фильтры и сравнение периодов

Панель: проект · период · модель · переключатель «Сравнить с предыдущими N дн.».

| Фильтр | Значения | Параметр URL | Поведение |
|---|---|---|---|
| Проект | список проектов + «все проекты» | `project` | по умолчанию все |
| Период | 30 / 90 / 180 / всё | `since_days` (`all` для «всё») | по умолчанию 90 (как сейчас); переключатель сегментами |
| Модель-ревьюер | список моделей из `by_reviewer_model` + «все» | `model` | влияет на разделы про ревью; на разделы без модели (cycle time, CFR, shift-left) не влияет, и это написано у панели («Модель влияет только на блоки про ревью») |
| Сравнение | вкл/выкл | `compare=prev` | включено по умолчанию, когда предыдущее окно той же длины существует; при «всё» выключено и объяснено |

Правила:
- Состояние целиком в URL: копирование ссылки воспроизводит страницу (#956 AC-4). Формы GET, без JS.
- Под панелью чипы активных фильтров; чип с фильтром, обнулившим выборку, помечен, кнопка «Сбросить фильтры».
- Панель sticky на десктопе, на мобильном обычный блок сверху.
- Смена фильтра пересобирает всю страницу на сервере.
- Предыдущее окно считается тем же кодом, что и текущее, с окном, сдвинутым назад на его длину (#956 AC-3, #1490).
- «Всё» без предыдущего окна: направление не рисуется.
- На `/metrics/agent-api` только окно (14/30/90; хранение 90 дней, дольше окна нет), сравнение с предыдущим. Проекта и модели у этой телеметрии нет, панель их не показывает.

## 11. Палитра и контраст

Тема тёмная, токены из `hub/static/style.css`. Расчёт контраста (WCAG 2.x) на `--surface` (#171a24) и `--bg` (#0c0e14):

| Токен | Значение | на surface | на bg | Использование |
|---|---|---|---|---|
| `--text` | #e4e7f0 | 14,04:1 | 15,61:1 | значения, оговорки |
| `--text-secondary` | #a0a5b8 | 7,08:1 | 7,87:1 | подписи, пояснения (замена `muted` для смысла) |
| `--text-muted` | #6b7084 | **3,53:1** | 3,93:1 | только для несмысловых элементов; текст с нагрузкой не использовать |

| красный (`--red`) | #e74c3c | **4,54:1** | 5,05:1 | только крупный текст и заливки |
| оранжевый (`--orange`) | #f39c12 | 7,92:1 | 8,80:1 | оговорка, «внимание» |

- Находка для #1487: заменить `.muted` в оговорках и «нет данных» на `--text-secondary`.

## 12. Мобильный вариант 375 px

Реализуется container queries на рамке страницы, без JS. В макете переключатель «Вариант 375 px»; проверено также эмуляцией 375×812: горизонтального скролла страницы нет.

| Элемент | ≥ 760 | 480–760 | < 480 (375) |
|---|---|---|---|
| Карточки показателей | 3 в ряд | 2 в ряд | 1 в ряд |
| Диаграммы | 2 в ряд | 1 в ряд | 1 в ряд |
| Панель фильтров | sticky, в строку | в блоке, переносится | вертикально, селекты и сегменты во всю ширину |
| Бары | подпись / полоса / значение | то же | подпись + значение, полоса ниже на всю ширину |
| Таблицы | как есть | как есть | строки-карточки (`data-label`), шапка скрыта визуально, но остаётся для скринридера |
| Проблемные места | 3 колонки (ранг / текст / ссылка) | то же | ранг + текст, ссылка под текстом |

Правила:
- Цели касания не менее 36×36 на десктопе, 44×44 на телефоне (селекты, сегменты, чекбокс, summary).
- Строки таблиц не сжимаются в 10 колонок: у профиля/харнесса/модели на мобильном каждая строка это карточка.
- Длинные идентификаторы полей и URL переносятся (`overflow-wrap:anywhere`).
- Шрифт значения 24 px, подписи не мельче 12 px.

## 13. Чек-лист доступности

- Один `h1`; `h2` на блок; порядок заголовков без пропусков.
- Панель фильтров: `role="search"`, метки у селектов связаны через `aria-labelledby`, сегмент `aria-current="true"` у выбранного.
- Диаграмма: SVG с `role="img"` и `aria-describedby` на текстовое описание, либо CSS-бары как список (`<ul>`), читаемый как список.
- Таблица-дубль в `<details>` у каждой диаграммы.
- Фокус виден: `outline` 2 px акцентом на `a`, `summary`, `select`, `input`.
- Цвет не единственный признак (§11).
- `prefers-reduced-motion`: анимация ширины столбцов только без предпочтения «меньше движения».
- Уровень контраста текста ≥ 4,5:1; проверка в CI не нужна, исполнитель прикладывает расчёт, если вводит новый цвет.
- Оговорка и пустое состояние читаются скринридером в порядке чтения рядом с числом.

## 14. Решения владельца (открытые)

Значения предложены, принятие макета их фиксирует. Любое можно поменять правкой в задаче.

1. Шесть ключевых показателей (§4).
2. `MIN_COMPARE_N` = 10 наблюдений в каждом окне (сейчас в хабе разные пороги: `MIN_SAMPLE`=20 в review_economy, `MIN_JUDGED_PER_SLICE`=20, `CFR_MIN_DEPLOYS`=5, `MODEL_CASCADE_MIN_SAMPLE`=5). Предложение: единый порог для дельты, пороги отображения долей остаются свои.
3. Порог «без изменений»: |Δ| < 5% относительно.
4. Порог попадания в «Проблемные места»: ухудшение ≥ 10%; порядок групп §7.
5. Модель как фильтр: применяется только к блокам про ревью (§8). Альтернатива: применять ко всей странице и обнулять то, что модель не различает.
6. Период по умолчанию 90, «всё» без сравнения.
7. Скриншоты «до/после» снимаются исполнителем #1487 (§1). Если владелец хочет «до» сейчас, отдельная просьба.

Побочные наблюдения, вне объёма: в `metrics.html` нет отдельного раздела для `shift_left` (данные есть в `practice_metrics.shift_left` и в CLI `oc-hub shift-left`), для `steward_shadow`, `executor_runs`, `model_declarations`, `validation_run_lines`. Спека не выдумывает для них макет. #1493 решает, какие включать в «Строки».
