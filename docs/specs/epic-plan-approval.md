# Допуск ограниченной версии плана

Этот контракт обслуживает пилот `receipt-split-calculator` и эпик #2373. В
снимке есть группы #2374–2376, допустимые листы #2377–2380, их ревизии,
области и зависимости доставки. Видны исключения, включая живую приёмку
#2381. Любые новые потомки присутствуют в новом снимке как исключённые.

Откройте «Допуск плана» на странице эпика или выполните
`hp-hub epic-plan show 2373`. API чтения соответствует
`GET /api/tasks/2373/epic-plan`. MCP `hub_epic_plan(epic_id=2373)` читает тот же
снимок и возможность принятия решения текущим принципалом.

## Кто принимает решение

Сервер читает `HAIPLANE_EPIC_PLAN_OWNER_PRINCIPAL_ID` как доверенное назначение
конкретного активного человеческого принципала пилота. Подходит DB-ключ или
браузерная сессия этого принципала с правом человеческого гейта. Режим open,
env-токены и chat-pair права решения не дают. Без явного назначения владельца
доступ к подписанию закрыт. Пилот не включает частные проекты.

Решение принимает текущую версию снимка. `POST /api/tasks/2373/epic-plan/approve`
принимает только `version`. Эквивалент CLI —
`hp-hub epic-plan approve 2373 --version <версия>`. Сохранённый снимок
включает саму версию проекта, идентификатор подписанта и точные условия.
Повтор возвращает ту же запись с первоначальным временем истечения.
Группы и готовые черновики открываются в одной транзакции штатного DoR.
Уже открытый лист сохраняет своё состояние и историю.

Интерфейс различает черновик, активный допуск, остановку, истечение и отзыв.
Остановка или отзыв принимает SHA версии и причину через `/terminate`,
веб-форму или команды `stopped` и `revoked`. Смена версии создаёт новое
решение. Ранее подписанный снимок сохраняется для аудита. Устаревшая
постановка, изменение проекта, графа, области, настроек или лимита блокируют
допуск до нового решения. В ленте событий есть одна человеческая активация,
а открытия черновиков ссылаются на неё как системные действия.

## Перед стартом

`hub.services.epic_plan.start_blocker` проверяет область, текущее решение,
срок, неизменность снимка и доставку блокирующих задач. Значение `None`
означает прохождение проверки допуска. #2383 должен вызвать её под той же
транзакцией, где он проверяет бюджет, WIP, повторы и резервирует заказ.
Действует меньший из согласованного, проектного и провайдерского лимитов.

Пока проверяемой брони расходов нет, старые двери платного запуска отказывают
для пилота. Сам допуск не создаёт заказов, не голосует по сдаче и не публикует
приложение. В других проектах действуют обычные гейты.
