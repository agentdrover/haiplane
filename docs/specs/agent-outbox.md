# Доставка результатов и вопросов ролей

Серверный контракт #2341 для адаптера K8 #1777. Хаб принимает сообщение от
включённого хоста, которому выдан действующий заказ роли. Хост передаёт
результат до завершения заказа. Статус доставки и ответ можно читать после
закрытия заказа. Права хоста на каждый запрос проверяет Хаб. Для private-проекта
нужно отдельное агентское делегирование, которого транспорт заказов не выдаёт.

## Отправка и подтверждение

1. Возьмите заказ через существующий `GET /api/executor-hosts/{host}/role-orders`
   и подтвердите старт. Сохраните локально ключ доставки и тело до первой отправки.
2. Прочитайте `GET /api/executor-hosts/{host}/role-orders/{order_id}/outbox`.
   Ответ содержит `project`, `role`, `task_id`, `generation` и `run` (номер
   попытки заказа). Добавьте эти поля к запросу публикации.
3. Отправьте `POST` на тот же адрес. Добавьте `lease_id` из заказа, стабильный
   `delivery_key`, `kind` и `body`. Для `question` укажите стабильный
   `continuation`. Для `result` и `silent` оставьте это поле пустым.
   `silent` принимает пустое тело и не создаёт сообщение.
4. Сохраните ACK `{id, state}`. Он свидетельствует о принятии Хабом. При
   потерянном ACK повторите исходный запрос. Повтор возвращает тот же ACK.
   Фактическое состояние читается через `GET …/outbox/{id}`.

Ключи доставки и продолжения — непрозрачные идентификаторы до 80 символов из
ASCII букв, цифр, точки, дефиса и подчёркивания. `delivery_key` уникален в
пределах принципала и проекта. Продолжение уникально в пределах попытки заказа.
Повтор ключа с другим нормализованным телом возвращает 409. Принадлежность
хоста, заказа и проекта проверяется перед чтением существующего ACK.
Нормализация убирает окружающие пробелы из текста. Запрещённые поля и известные
формы секретов отклоняются с безопасным 422. Передавайте только текст, пригодный
для журнала и карточки. Ключ доступа хоста находится в заголовке Authorization.
Nonce lease проверяется при публикации и отсутствует в записи, событии и ответе.

CLI `hp-hub agent-outbox scope HOST ORDER` читает привязку, `publish HOST ORDER`
принимает JSON из stdin, `status HOST ORDER ID` читает доставку. MCP
`hub_agent_outbox` использует тот же API с настроенным ключом хоста.

## Состояния доставки

| Состояние | Что наблюдал Хаб |
| --- | --- |
| `pending` | Хаб принял результат. Worker ещё не зафиксировал сообщение |
| `sent` | Worker записал сообщение, событие и ID сообщения в одной транзакции. Для `silent` сообщение отсутствует |
| `failed` | Запись сообщения прекращена. Поле `reason` содержит причину |
| `unknown` | Ошибка хранилища или прерванные попытки исчерпали лимит. Наблюдения о доставке нет |

Worker берёт до 20 записей за проход. Lease действует 60 секунд. После
временной ошибки пауза растёт с 60 секунд до часа, попыток не более восьми.
Неподтверждённая доставка истекает после суток. Лимит приёма на принципала —
100 pending и 120 новых операций за час. Ответ 429 оставляет ключ доступным
для повтора. Остановка worker сохраняет pending. Терминальные записи хранятся
14 дней с приёма. Существующее хранение сообщений и событий действует отдельно.
После окна хранения не повторяйте ключи старых операций.

Сообщение, событие и ACK доставки используют одну локальную транзакцию SQLite.
При сбое до commit откатываются все три записи. При сбое после commit
повтор видит `sent`. Это относится только к локальному Hub messaging.

## Ответ и продолжение

Вопрос отображается в «Сообщениях сессий» карточки задачи. Владелец задачи
отвечает через форму, `POST /api/tasks/{task_id}/outbox-questions/{message_id}/answer`
с `{"body":"…"}` или `hp-hub agent-outbox answer TASK MESSAGE` со stdin.
Повтор того же ответа возвращает прежний ID. Другой текст после ответа даёт 409.

Ответ записывается в ту же ветку сообщений, адресуется исходному хосту и
публикуется через существующее событие `message_posted`. Оно несёт ссылку на
сообщение. Делегату, которому разрешён общий поток событий, доступны обычные
правила адресации. Ключ хоста читает только состояние своей доставки.
Для #1777 поле `answer_event_id` — ID того же события для устойчивой корреляции.
`continuation_state=answered` даёт `continuation` и ответ. В состоянии
`stale` поле `continuation_reason` называет изменившееся условие, а текст
ответа скрыт. Проверяются допуск, попытка, владелец, поколение и заход задачи.

Ответ — сообщение владельца. Перед следующим действием адаптер читает
актуальный статус и выполняет предусмотренные для действия проверки прав
и человеческий гейт. Наступление таймаута права не выдаёт.
