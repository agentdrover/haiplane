# Паспорт постоянного агента

Паспорт v1 описывает постоянные роли проекта и текущее состояние связанных
гейтов. Hub формирует его при чтении. Перед действием заново проверяется
действующая политика и авторизация.

Откройте «Паспорт агента» в карточке проекта, вызовите
`GET /api/projects/{slug}/agent-passport` или `hub_agent_passport(project=...)`.
`hp-hub projects passport <slug>` выводит серверный текст, опция `--json`
выводит полный контракт. Bootstrap добавляет `agent_passport` и раздел 7
к существующему пакету.

## Декларация

Hub читает `.hub/AGENT_PASSPORT.json` на базовой ветке серверного клона.
Пример декларации роли и даты её следующей проверки:

```json
{
  "schema_version": "1",
  "review_by": "2027-01-31",
  "roles": [
    {"role":"executor", "runtime":"codex", "events":"task_assignment", "memory":"hub_task"}
  ]
}
```

Роли `executor`, `roadmap`, `infrastructure` указываются по одному разу.
Разрешённое значение `runtime` — `codex` (по умолчанию). События принимают
`task_assignment`, `hub_events`, `infra_alerts`. Память принимает `hub_task`,
`hub_roadmap`, `infra_checkpoint`. Поля `review_by`, `events` и `memory` можно
опустить. Дата проверки считается по UTC. Истёкшая дата помечает декларацию
`stale`. Неизвестная версия, неизвестное поле, повтор роли и файл больше
лимита чтения помечают декларацию `invalid`. Hub показывает код состояния
и фиксированный источник без содержимого файла и внутренних причин чтения.

Пилотная декларация Hub используется при отсутствии либо недоступности
файла у `default` (исполнитель и roadmap) и `home-infra` (инфраструктура).
Состояние чтения файла остаётся видимым. Пустой список ролей в читаемой
декларации сохраняется. Инфраструктурная роль показана как планируемая.

## Политика и факты

Каждый факт имеет состояние, источник и при наличии дату наблюдения.
Выбранные значения pipeline, бюджетов и настроек прав берутся из тех же
читателей, что и effective policy. Произвольные команды, пути, данные
хостов и реквизиты токенов не включаются в паспорт. Старт roadmap из
`role_orders` подтверждает наблюдение работы роли, но не семейство runtime.
Наблюдение старше суток помечается `stale`. Модель сервиса и запуск
принятых задач сами по себе не подтверждают постоянный runtime. Проверка
runtime остаётся `unknown` до появления источника приёмки постоянной роли.

Доступ к паспорту и bootstrap использует права чтения и область ключа.
Для частного проекта действует решение о членстве проекта. Все поверхности
паспорта вызывают одно серверное представление. Просмотр не меняет состояние.
