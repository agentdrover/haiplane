# Проект на GitVerse: чего требует доставка

Документ описывает одно условие и одно следствие. Оба измерены на живом API
01.09.2026, а не выведены из документации вендора.

## Условие: базовая ветка открыта для push аккаунтом хаба

В публичном API GitVerse **нет вызова, который выполняет мерж**. Есть только
`GET /repos/{owner}/{repo}/pulls/{n}/merge`, и он отвечает на вопрос «влит
ли уже», а не сливает.

Поэтому хаб доставляет работу локальным git: `merge --no-ff` ветки задачи в
базовую и `push`. Другого пути нет. Отсюда требование: **базовая ветка
GitVerse-проекта не может быть закрыта от прямого push для того аккаунта,
которым ходит хаб.**

Это слабее, чем на GitHub, где мерж идёт вызовом API с обходом защиты по
роли. Ослабление осознанное и это плата за отсутствующий endpoint; когда
GitVerse опубликует мерж, обход снимается вместе с требованием.

Если ветку всё же закрыть, доставка не встанет молча: она откажет и назовёт
причиной именно защиту базовой ветки, а задача уйдёт к человеку.

## Следствие: состояние PR ничего не говорит о доставке

Измерено: после настоящего `merge --no-ff` и `push` GitVerse **не замечает**,
что голова влита. PR остаётся `open`, `merged=False`, `merged_at=null`,
`merge_commit_sha=null`, а `GET /pulls/{n}/merge` отвечает 404 и до, и после
мержа.

Из этого следуют две вещи, которые видно снаружи:

1. **Доставка подтверждается базовой веткой**, а не PR: хаб проверяет, что
   полученный коммит достижим в базе на remote. Проверка через PR объявила бы
   доставленную работу недоставленной.
2. **PR закрывает сам хаб** после подтверждения. Иначе он висел бы открытым
   вечно, и поиск PR по ветке находил бы его на уже доставленной работе.

Побочно: доставленный хабом PR и брошенный человеком через API неразличимы —
оба `closed`, `merged=False`. Поэтому состояние PR на GitVerse не
используется как признак доставки нигде.

## Ловушка импортированного репозитория

У репозитория, перенесённого с GitHub, остаются рефы `refs/pull/N/head`. Они
выглядят в точности как гитхабовские, но **нативных PR за ними нет**, а
нумерация новых PR начинается с единицы и с ними коллидирует. Выводить
существование PR из наличия рефа нельзя: единственный источник — API.
