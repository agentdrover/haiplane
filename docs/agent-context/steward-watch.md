# Дежурство стюарда: хук будит сессию по ящику роли (#1680)

Хаб кладёт наблюдательные уведомления в ящик `steward@<проект>` (#1679), ящик
роли читает сессия, зарегистрированная с `work_role=steward` (#1678). Хук
`.claude/hooks/hub_wait_hook.py` ждёт этот ящик постоянно и будит сессию без
потерь. Тело сообщения остаётся данными: хук его не печатает.

## Как это устроено

Два файла, у каждого один владелец.

| Файл | Владелец | Что внутри |
| --- | --- | --- |
| `.claude/hub-wait.<sid>.json` | агент | запись `{"kind":"watch","owner":"<sid>","session_id":"<sid>","acked_id":N}` рядом с прочими ожиданиями |
| `.claude/hub-wait.<sid>.watch-state.json` | хук | `accepted_id` — принятый курсор; `issued` — выданный диапазон `{from,to,ids}` или `null` |

Порядок работы хука на каждом цикле:

1. Нет `issued`: хук читает ящик постранично после `accepted_id` (все страницы,
   по 20), записывает в `issued` ВСЕ новые id (не больше 200; остаток придёт
   следующим диапазоном) и будит сессию (exit 2). Ошибка HTTP на любой странице:
   `issued` не создаётся, пробуждения нет, повтор на следующем цикле.
2. Есть `issued`: новые сообщения диапазон не расширяют, каждый Stop будит
   снова тем же диапазоном. Refire-кап на watch не действует.
3. В пробуждении каждый id идёт с разрешёнными полями. Уведомление хаба v1
   (`from_agent=hub`, пустой `from_session_id`, закрытая схема, `project_slug`
   совпадает с адресом `steward@<slug>`): `reason`, `project_slug`, `task_id`,
   `source_event_id`. Всё остальное, включая поддельный v1 и битый JSON: только
   id, отправитель и тип, без тела.
4. Подтверждение делает проснувшийся агент: правит в своей записи watch ТОЛЬКО
   `acked_id`, ставит значение `issued.to` из пробуждения. Остальные ожидания
   файла не трогать. Новый процесс хука сверяет значение со своим состоянием.
   `acked_id == issued.to`: диапазон принят, `accepted_id = issued.to`,
   `issued = null`. Любое другое значение, кроме текущего `accepted_id`, хук
   отклоняет вслух и состояние не меняет.
5. Сообщение старше 14 дней (ретенция) из ящика исчезает. Хук не подтверждает
   такой диапазон сам: id выводится как «недоступен (ретенция)», агент
   подтверждает вручную. Если хаб не ответил, id выводится как «содержимое не
   получено»: отсутствие ответа не значит «удалено».

Watch берётся только при известном `session_id` (payload Stop или переменная
окружения). Без него watch-записи не читаются и не меняются, остальные
ожидания работают как раньше. Цикл с watch не выходит по `MAX_WAIT_SEC`;
обычные ожидания и `kind=message` в том же файле живут свои 4 часа и по
прежним правилам.

## Включение

1. Регистрация хука в `.claude/settings.local.json` (файл в git не
   коммитится):

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/hub_wait_hook.py\"",
            "asyncRewake": true
          }
        ]
      }
    ]
  }
}
```

2. Регистрация сессии: `hub_session_register(session_id=..., work_role="steward",
   projects=["<slug>", ...])`. Без роли и проектов ящик роли пуст.
3. Heartbeat раз в TTL сессии (по умолчанию 10 минут): `hub_session_heartbeat`.
   Опрос ящика присутствие не обновляет; сессия без heartbeat выпадает из
   адресатов роли.
4. Запись ожидания в `.claude/hub-wait.<sid>.json`:

```json
{"waits": [{"kind": "watch", "owner": "<sid>", "session_id": "<sid>",
            "acked_id": 0, "reason": "дежурство стюарда"}]}
```

   Начальный `acked_id` задаёт стартовый курсор, пока у хука нет своего
   состояния; дальше курсор ведёт хук.
5. Проснулся: прочитай сообщения `hub_inbox`, обработай, потом подтверди.
   Подтверждение пишется атомарно (временный файл и rename) и меняет одно поле.
   Если диапазон недоступен по ретенции, подтверди так же вручную.

## Проверка: пробуждение за 2 минуты

Сценарий для метрики задачи (10 прогонов из 10):

1. Включи хук и запись watch по шагам выше, закончи ход (Stop).
2. С другой сессии отправь сообщение роли: `hub_send_message` с
   `to_kind="role"`, `to_ref="steward@<slug>"` (или дождись уведомления хаба).
3. Запиши время до пробуждения: хук слушает фид хаба и просыпается за секунды,
   запасной опрос идёт раз в 15 секунд. Цель: не больше 2 минут.
4. Подтверди диапазон и повтори.

Боевая метрика: число диапазонов `issued`, которые остаются неподтверждёнными
дольше часа при живой сессии. Цель: 0. Смотреть по
`.claude/hub-wait.<sid>.watch-state.json`: поле `issued` не `null` и файл не
менялся больше часа.
